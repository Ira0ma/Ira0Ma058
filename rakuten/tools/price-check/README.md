# 価格チェッカー（実ブラウザ版）

楽天の商品ページを Playwright の Chromium で開き、**価格・在庫・バリエーション・リンク先** を基準値と突き合わせます。
投稿直前の人の照合を置き換えるものではなく、差異のあるものを拾って人の確認に回すための下支えです。

## 準備（初回だけ）

```bash
cd rakuten/tools/price-check
npm install                 # playwright
npx playwright install chromium
```

## 実行

```bash
# price_watch_log.csv から、指定した投稿だけ（同じ投稿の行が複数あれば最新の行を基準に）
node price_check.js --input price_watch_log.csv --post-id R0012 --post-id R0015 --latest-per-post --out-dir out

# CSV の行番号で指定（見出しを除いて1から）
node price_check.js --input targets.csv --row 3 --row 4 --out-dir out

# 1件だけ
node price_check.js --url https://item.rakuten.co.jp/<shop>/<item>/ --baseline 1980 --out-dir out
```

入力 CSV には `item_url` と `baseline_price_yen` の列が必要です（`post_id`・`item_name` があれば出力に引き継ぎます）。
出力は `out/price_check_<日時>.csv / .md / .json` に **新しく** 書きます。同じ名前のファイルがあれば書かずに失敗します。
`price_watch_log.csv` や `posts.csv` には書き込みません。採用する行は、人が確認してから転記してください。

| 出力 | 中身 |
|---|---|
| `.md` | 点検担当用の表：判定・理由・基準価格・実測価格・価格の一致・リンク先の一致・在庫・バリエーション（全点）・確認時刻・対象URL |
| `.csv` | `price_watch_log.csv` と同じ12列（status＝判定、source＝`playwright:json-ld` など読み取り元、note＝理由） |
| `.json` | 全項目（開いた後のURL、バリエーションの内訳、遮断した書き込みリクエスト数） |

終了コード：0＝最後まで実行、2＝途中で停止（ボットチェック・接続不可・取得不可が3件連続）、1＝入力エラー。

## 判定

| 判定 | 条件 |
|---|---|
| 一致 | 価格＝基準値、在庫あり、開いたページが対象商品（ショップ／商品コードが一致）、バリエーション間で価格差なし |
| 差異あり | 上のうち1つでも食い違う（価格差、在庫なし・予約・販売終了、リンク先不一致、価格の幅、バリエーション価格差） |
| 要確認（在庫のみ取得不可） | 価格とリンク先は一致、在庫だけ読めない。一致した事実（価格・リンク先の列）は残して人の確認に回す |
| 要確認（バリエーション一部取得不可） | 食い違いはないが、一部のバリエーションの価格が読めない。読めたバリエーションの一覧は残して人の確認に回す |
| 取得不可 | 下の理由つき |

バリエーションが読めたときは、価格差の有無にかかわらず **全点の価格と在庫の一覧** を出力に付けます（`.md` のバリエーション列、`.csv` の note）。
バリエーション間で価格が違う場合は、投稿側の価格表記（範囲か単一価格か）で意味が変わるため、道具では決めずに「差異あり」で人の確認に回します。

| 取得不可の理由 | 判定のしかた | 続行 |
|---|---|---|
| ボットチェック | HTTP 403/429、またはタイトル・本文先頭に CAPTCHA・「ロボットではありません」等 | **止める** |
| 接続不可（ネットワーク・プロキシ） | 名前解決・プロキシ・回線のエラー | **止める** |
| ページ不存在 | HTTP 404/410、タイトルが「ページが見つかりません」等、商品ページ以外へ移動 | 続ける |
| 一時的な読み込み失敗 | タイムアウト、HTTP 5xx | 続ける（3件連続で止める） |
| 価格を読み取れず | ページは開けたが、構造化データ（JSON-LD・microdata）に価格がない | 続ける |

価格・在庫は **商品ページ内の構造化データ（schema.org の JSON-LD → microdata の順）だけ** から読みます。
見た目の文字（「売り切れ」など）や、おすすめ欄の別商品の価格を拾わないためです。読み取り元は `source` 列に残ります。

## アクセスの約束

- 読み取り専用：クリック・入力をしない。GET/HEAD/OPTIONS 以外のリクエスト（カート追加・フォーム送信・計測の POST など）はブラウザ内で遮断する
- 間隔：ページ間 20秒＋0〜10秒のゆらぎ（楽天のページは 10秒未満に設定できない）。1回の上限 20件
- ボットチェックが出たら、その場で止めて残りは開かない。回避の細工（UA偽装・待ち時間の操作・CAPTCHA突破）はしない
- 毎回新しいブラウザ（Cookie を持ち越さない）

## テスト

```bash
node --test tests/*.test.js
```

ローカルに立てた **合成ページ** で、一致／差異／後から JS で出る価格／404／リダイレクト先不一致／ボットチェックで停止／POST 遮断を確認します。楽天には接続しません。
