## 1. 調査で見つけた問題と根拠

| # | 問題 | 根拠（変更前のコード） | 対応 |
|---|---|---|---|
| P1 | **本番でも架空のローソク足が出る経路があった**。価格を受け取った後（`live=true`）に、履歴が2本以下の時間足へ切り替えると、乱数で作った足を描いていた | `Market.prototype.gen`：実データがないと `rng()` で生成。`draw()` は `!this.live && !PREVIEW` のときだけ止めていた | 修正：本番では生成しない。「◯◯のデータは未取得です」と表示 |
| P2 | 最新価格を、時刻に関係なく最後の足に上書きしていた（1分足が10分古いと、今の価格が10分前の足に入る） | `applyLive`：`last.c = p` | 修正：価格の時刻が属する足に反映。1時間以下は新しい形成中の足を作る。4時間・日・週はサイトの更新を待つ（業者のサーバー日に合わせるため推測しない） |
| P3 | 休場と通信障害が区別されていなかった（3時間以上前の価格を一律「終値」と表示） | `render`：`now - at > 3h ? " 終値" : " 時点"` | 修正：銘柄ごとの取引時間で休場を判定し、「休場中」と「停止」を分けた |
| P4 | 価格の提供元・種類（仲値・売値換算・補正値など）が画面に出ていなかった | カードには時刻のみ | 修正：カードのチップとデータ状態画面に表示 |
| P5 | `market.json` の応答順が逆転すると古いデータで上書きされうる／形式・数値の検査がない | `loadMarket` が順序・形式を見ていなかった | 修正：連番で古い応答を破棄、`updated` が古いコピーは採用しない、銘柄ごとに検査して不合格は前回値を保持（なければ「データ確認中」） |
| P6 | エントリー通知の重複抑止が「直前の状態」だけで、判定の根拠・期限・履歴がなかった | `entry && !was` で鳴らすだけ | 修正：シグナル履歴（後述） |
| P7 | 新しい版を検出すると、操作中でもページを自動で再読み込みしていた | `checkUpdate` → `location.replace` | 修正：案内を出し「今すぐ更新／あとで」を選べる（ダッシュボード単独表示も同様。デスクの裏で動くダッシュボードは従来どおり自動） |
| P8 | 一致度スコア（例「買い優勢 97」）が確率のように見える | 説明なし | 一部対応：算出方法と「勝率・確率ではない」をバッジの説明とシグナル画面に記載。分析が古いときは取り消し線で参考外 |
