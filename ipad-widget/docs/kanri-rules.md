# Trade Desk Home 管理ルール

- 対象アプリ：https://ira0ma.github.io/Ira0Ma058/
- オーナー：Yam（変更の最終許可と本番反映の承認）
- 管理・検収担当：Muse（診断、指示書の作成、実装後のライブ確認）
- 実装担当：指示書の範囲内での実装と調査、完了報告

（2026年11月1日の指示書より保存）

## 絶対ルール

1. 1回の作業は1つの目的だけ。「ついで」の機能追加・改修はしない。必要と感じたら止めて、別タスクとして提案する。
2. 指示された範囲以外は触らない。範囲を広げる必要が生じたら、変更前に理由を報告し、オーナーの許可を待つ。
3. 価格データは単一の取得経路・単一の保存先を正とする。画面ごとに別方法で価格を取得しない。新しい取得経路を作る前に、既存経路で代替できないか検討し、理由を報告する。
4. 新しい外部API・外部サービスの追加・登録、課金が発生する契約、APIキーの新規発行・設定変更は、オーナーの許可なく行わない。既存APIが使えない場合も勝手に代替サービスへ乗り換えない。
5. 日時・市場時間などの定義は一元化する。画面ごとに独自の時刻定義を持たない。市場再開時刻を表示する場合は、取引所とブローカーのどちらの時刻かを併記する。
6. 表示する数値には、可能な限り「取得元・更新時刻・状態（最新／遅延／停止／未取得）」をセットで扱い、古い値を新しい値のように見せない。
7. 秘密情報（APIキー等）をコードや報告に平文で書かない。
8. ユーザーデータ（ブラウザ内保存の日誌・設定など）の削除、初期化、外部送信、保存形式の変更は、方法を先に提示して許可を得てから行う。
9. 本番環境（GitHub Pages）への反映を伴う push は、指示書で明示された作業について、オーナーがそのセッション内で「反映してよい」と言った後にのみ行う。
10. 作業が終わったら、必ず「完了報告の様式」で報告する。確認できなかった項目は「未検証」と正直に書く。推測を事実のように書かない。

## 完了報告の様式（作業ごとに出す）

- タスク名：
- 変更内容の要約：（実装の場合のみ、3行以内。調査の場合は調査結果の要約）
- 変更ファイル一覧：（ファイル名と変更の概要。変更なしの場合は「なし」）
- 完了条件への対応：（条件ごとに、満たした／満たしていない と理由）
- 実施したテスト：（変更箇所の確認結果と、回帰チェックの結果）
- 未検証の項目：（なければ「なし」）
- 新たに見つけた問題・気づいた点：（勝手に直さず、提案として書く）
- オーナー・管理担当への確認事項：（判断が必要な点）

## 進め方で迷った場合

- 解釈が2通りに取れる場合は、作業を止めてオーナーに質問する。自己判断で広げない。
- 完了条件を満たせない場合は、満たせない理由と、取り得る代替案を報告して止まる。条件を勝手に緩めない。

- `ipad-widget/docs/` は公開サイトにはコピーされない。
